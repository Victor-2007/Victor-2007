Temporal Glycemic Patterns — CGM Analytics + R Shiny Dashboard

Large-scale observational study linking Dexcom CGM device data (2015–2020) with Veterans Health Administration electronic health records to characterize long-term glucose trajectories in 892 T1D and 1,716 T2D patients. Co-developed the interactive data dashboard for the published paper in the Journal of Diabetes Science and Technology.

R tidyverse R Shiny linear mixed-effects models time-series EHR linkage
  • Processed 2.1M+ CGM readings across nearly three years per patient; computed daily mean glucose (MG), time-in-range (TIR), coefficient of variation (CV), and time-below/above-range metrics
  • Built 30+ interactive visualizations in R Shiny covering three-year longitudinal trends, year-round seasonal overlays, day-of-week patterns, and subgroup stratifications (baseline HbA1c, CGM usage frequency, U.S. region)
  • Uncovered recurring patterns: Sundays consistently had the highest glucose (~3 mg/dL above Wednesday); winter months (Oct–Feb) showed deterioration vs. spring/summer rebound; higher CGM usage frequency was associated with attenuated glucose rise over time
  • Analyses used linear mixed-effects models with random intercepts/slopes, Bonferroni-corrected confidence intervals, and stratified subgroup comparisons by pre-CGM HbA1c and geographic region (Northeast vs. Southwest)
  • Maintained a collaborative GitHub workflow for reproducible analysis across the research team (UCLA Biostatistics, Phoenix VA, Université Paris-Saclay)

TB Drug-Synergy Screening Pipeline (INDIGO-MTB + TACTIC + M2D2)

Computational pipeline for prioritizing anti-tuberculosis drug combinations. Extended the INDIGO-MTB framework — which uses pathogen transcriptomic profiles to predict synergy/antagonism — by integrating M2D2-generated drug-protein interaction features with TACTIC's cross-species transfer-learning approach, replacing traditional chemogenomic inputs with structure- and sequence-derived ML features to enable predictions for under-studied bacterial strains.

MATLAB INDIGO-MTB TACTIC M2D2 transfer learning ComBat ETL
  • Ran high-throughput INDIGO-MTB prediction jobs screening 100,000+ drug combinations (2-way, 3-way, 4-way) with repeatable batch logging and standardized Excel exports for lab triage
  • Integrated M2D2's two-stage ML pipeline (drug-target affinity prediction → drug-drug interaction prediction) to generate structure-derived feature vectors, replacing the traditional chemogenomic/transcriptomic inputs required by INDIGO
  • Leveraged TACTIC's transfer-learning framework — trained on ~3,000 drug interactions across 12 bacterial strains from 6 species — to enable cross-species predictions for M. tuberculosis strains that lack sufficient training data on their own
  • Built the ETL layer: ingested new transcriptome/fitness files, aligned by gene ID, imputed missing values (median fallback), and ran ComBat batch correction to produce a single corrected matrix for all downstream predictions
  • Computed Pearson/Spearman correlations and p-values between prediction vectors across conditions to rank candidates; prioritized Spearman for robustness against outliers
  • Generated ranked candidate shortlists and analysis-ready exports for lab collaborators to guide follow-up wet-lab testing
Research Summary ↗
MATLAB pipeline overview
1) Append condition → impute → ComBat

Ingest a new transcriptome/fitness file, align rows by gene ID, fill missing values per-column (median fallback), and run ComBat to remove batch effects. Output: a single corrected expression matrix for all downstream predictions.

2) Build phenotype features

Convert corrected expression into a z-thresholded phenotype representation so the INDIGO model can compare conditions consistently. Boolean operations (union/intersect) capture both similarity and uniqueness of drug-target profiles.

3) Train → predict → export ranked combinations

Train on curated interaction data using bagged random forest / SVM regressors, then run batched predictions for 2/3/4-way drug combos. Export standardized tables (ranked by predicted FIC score) for sorting and lab triage.

4) M2D2 integration

Replace traditional chemogenomic inputs with M2D2-generated drug-protein affinity features (binarized using optimal z-score cutoffs). Feed these into TACTIC's transfer-learning pipeline to predict antimicrobial interactions across species without requiring species-specific training data.

5) Correlation + p-values (reporting)

Compute Pearson/Spearman correlations between prediction vectors and report p-values to quantify cross-condition agreement. Rank primarily by Spearman for robustness.

Einstein / Montefiore: Inhibiting the Inceptor–Insulin Receptor Interaction

Structure-based computational drug discovery study targeting the insulin inhibitory receptor (inceptor), discovered in 2021, which drives insulin resistance by binding to insulin receptors on cell surfaces, triggering endocytosis and reducing the number of available receptors. This multi-faceted approach combined protein complex modeling, binding site identification, virtual screening, molecular docking, and mutation analysis to identify candidate molecules that could disrupt the inceptor–insulin receptor interaction.

AlphaFold Multimer virtual screening molecular docking FASPR PRODIGY Java Apache POI
  • Filtered both protein sequences to extracellular domains (inceptor residues 42–910, insulin receptor residues 28–956) using UniProt, then modeled the complex 5× with AlphaFold Multimer for accuracy
  • Converted PDB files to Excel with cartesian coordinates, atom type, residue info, occupancy, and beta factor; wrote Java utilities (Apache POI) to flag carbon-alpha residues within 10 Å across molecule groups and cross-reference all 5 models into a residue-level probability table
  • Identified binding-site residues at 100% consensus across all 5 models; screened 6,507 candidate small molecules via FindSITE Comb virtual screening and docked the top 10 with MTI Autodock
  • Top candidates: beta-L-fucose, beta-D-fucose, and alpha-L-fucose showed the strongest binding energies, suggesting they could effectively occupy the inceptor binding site and block interaction with the insulin receptor
  • Computationally mutated insulin receptor binding-site residues using FASPR (side-chain conformation prediction) and measured changes in binding energy (ΔΔG) with PRODIGY — the R926W mutation produced the largest shift (0.4 kcal/mol)
  • Linked discovered mutations to three rare insulin-resistance disorders: IRAN type A, Leprechaunism (Donohue syndrome), and Rabson-Mendenhall syndrome, suggesting mutations affect disease primarily through altered inceptor–receptor binding

1) Distance-based "interest" flagging in Excel (Apache POI) 
package excelOperations;

import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;

import org.apache.poi.ss.usermodel.CellType;
import org.apache.poi.xssf.usermodel.*;

/**
 * Reads a single Excel sheet containing two sets of 3D coordinates (e.g., Molecule B and Molecule C).
 * For each Molecule B row, it checks whether any Molecule C row lies within a threshold distance.
 * Writes an "Interest" column (Yes/No) for Molecule B rows.
 */
public class ReadingExcel {

  public static void main(String[] args) throws IOException {
    if (args.length < 1) {
      System.out.println("Usage: java ReadingExcel <input.xlsx>");
      return;
    }

    String excelFilePath = args[0];
    double threshold = 10.0;

    try (FileInputStream in = new FileInputStream(excelFilePath);
         XSSFWorkbook workbook = new XSSFWorkbook(in)) {

      XSSFSheet sheet = workbook.getSheetAt(0);

      XSSFRow headerRow = sheet.getRow(0);
      XSSFCell headerCell = headerRow.createCell(12, CellType.STRING);
      headerCell.setCellValue("Interest");

      int lastRow = sheet.getLastRowNum();

      for (int i = 1; i < 870; i++) {
        XSSFRow rowB = sheet.getRow(i);
        double xB = rowB.getCell(6).getNumericCellValue();
        double yB = rowB.getCell(7).getNumericCellValue();
        double zB = rowB.getCell(8).getNumericCellValue();

        boolean isOfInterest = false;
        for (int j = 870; j <= lastRow; j++) {
          XSSFRow rowC = sheet.getRow(j);
          double xC = rowC.getCell(6).getNumericCellValue();
          double yC = rowC.getCell(7).getNumericCellValue();
          double zC = rowC.getCell(8).getNumericCellValue();

          double dx = xC - xB, dy = yC - yB, dz = zC - zB;
          double distance = Math.sqrt(dx*dx + dy*dy + dz*dz);

          if (distance < threshold) { isOfInterest = true; break; }
        }

        XSSFCell interestCell = rowB.createCell(12, CellType.STRING);
        interestCell.setCellValue(isOfInterest ? "Yes" : "No");
      }

      try (FileOutputStream out = new FileOutputStream(excelFilePath)) {
        workbook.write(out);
      }
    }
    System.out.println("Done");
  }
}

          double xB = rowB.getCell(6).getNumericCellValue();
          double yB = rowB.getCell(7).getNumericCellValue();
          double zB = rowB.getCell(8).getNumericCellValue();

3) Aggregating across multiple models (probability-style summary) 
package excelOperations;

import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;
import java.util.HashMap;
import java.util.Map;

import org.apache.poi.ss.usermodel.CellType;
import org.apache.poi.xssf.usermodel.*;

/**
 * Loads multiple model output files, counts how many models
 * mark each row as Interest="Yes", and writes a summary into a master sheet.
 */
public class ProbabilityAggregator {

  public static void main(String[] args) throws IOException {
    if (args.length < 2) {
      System.out.println("Usage: java ProbabilityAggregator <master.xlsx> <model1.xlsx> ...");
      return;
    }

    String masterPath = args[0];

    Map<String, XSSFSheet> sheets = new HashMap<>();
    Map<String, XSSFWorkbook> books = new HashMap<>();

    for (int i = 0; i < args.length; i++) {
      String path = args[i];
      try (FileInputStream in = new FileInputStream(path)) {
        XSSFWorkbook wb = new XSSFWorkbook(in);
        XSSFSheet sh = wb.getSheetAt(0);
        String key = (i == 0) ? "MASTER" : ("MODEL" + i);
        sheets.put(key, sh);
        books.put(key, wb);
      }
    }

    XSSFSheet masterSheet = sheets.get("MASTER");

    for (int rowNum = 1; rowNum <= masterSheet.getLastRowNum(); rowNum++) {
      int yesCount = 0;
      for (String name : sheets.keySet()) {
        if (name.equals("MASTER")) continue;
        XSSFRow row = sheets.get(name).getRow(rowNum);
        if (row == null) continue;
        XSSFCell cell = row.getCell(12);
        if (cell != null && "Yes".equalsIgnoreCase(cell.getStringCellValue())) {
          yesCount++;
        }
      }

      XSSFRow outRow = masterSheet.getRow(rowNum);
      if (outRow == null) outRow = masterSheet.createRow(rowNum);
      XSSFCell outCell = outRow.createCell(9, CellType.STRING);
      outCell.setCellValue("Yes in " + yesCount + " models");
    }

    try (FileOutputStream out = new FileOutputStream(masterPath)) {
      books.get("MASTER").write(out);
    }

    for (Map.Entry<String, XSSFWorkbook> e : books.entrySet()) {
      if (!e.getKey().equals("MASTER")) e.getValue().close();
    }
    books.get("MASTER").close();
    System.out.println("Aggregation complete.");
  }
}

Consolidates results from multiple model runs, counting how many flagged each row as "Interest = Yes."
